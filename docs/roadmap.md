## 每次迭代怎么执行

每个大型功能都遵循同一套流程：

```text
明确用户场景
→ 定义本次范围和明确不做的内容
→ 设计接口与数据流
→ 先实现后端核心
→ 接前端页面
→ 补自动测试
→ 浏览器端到端验证
→ 补中文教程
→ 大功能更新 README
→ commit
→ push
→ 更新本路线图
```

### 一个里程碑的完成标准

只有同时满足以下条件，才算“完成”：

- 用户可以在浏览器实际操作。
- 后端有真实业务逻辑，不是静态 Mock 页面。
- 至少有一个正常路径测试和一个失败路径测试。
- 前端类型检查通过。
- 后端测试通过。
- 文档说明当前能做什么、不能做什么。
- 代码已提交并推送到 GitHub。

## Git 记录规范

```text

docs: 对应教程、README、路线图
```

提交后必须推送：

```bash

```

然后更新本文件的：

1. 当前状态。
2. 当前 Git 基线。

4. 下一个当前开发阶段。

## 教程和路线图的区别

- `docs/roadmap.md`：记录“项目做到哪里，下一步做什么”。
- `docs/tutorials/`：解释“为什么这样做，代码怎样运行”。
- `README.md`：给第一次访问项目的人展示“项目是什么，现在能做什么”。
- `docs/architecture.md`：解释稳定的系统结构和设计规则。

任何一个文件都不应该重复承载全部信息。
