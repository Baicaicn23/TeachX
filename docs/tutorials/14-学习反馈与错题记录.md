# 14：学习反馈与错题记录

## 这一章解决什么问题

普通聊天只能告诉模型“我刚才问了什么”，却不能告诉它：

- 哪一类讲解真正有帮助。
- 哪些解释让人仍然不清楚。
- 学习者具体把哪个概念混淆了。
- 怎样在后续对话中继续处理同一个误区。

U4 增加了一条最小学习反馈闭环：

```text
导师回答
→ 标记“有帮助”或“不清楚”
→ 或记录“我的理解误区”
→ 在学习记录页统一查看
→ 把误区带回聊天继续弄懂
→ 随时删除自己的记录
```

它不是管理员统计，也不是给回答打公开评分。记录只属于当前用户，目的是帮助下一次
解释更贴近学习者。

## 为什么不直接写进消息 metadata

反馈看起来只是回答上的一个小标签，但直接塞进 `messages.metadata` 会带来几个问题：

- 一个用户只能修改自己的消息，跨用户权限很难单独校验。
- 记录页需要跨会话查询，JSON 内嵌字段不容易建立清晰索引。
- 删除反馈需要同时修改原消息，容易把聊天内容和反馈状态耦合在一起。
- 同一个回答未来可能出现更多学习动作，不应无限扩展消息 metadata。

所以 U4 使用独立表：

```text
answer_feedback
```

主要字段：

```text
id
user_id
session_id
message_id
rating
note
created_at
updated_at
```

其中：

- `rating` 只能是 `helpful`、`unclear` 或 `wrong`。
- `note` 保存学习者写下的理解误区。
- `user_id + message_id` 唯一，保证一个用户对一条回答只有一个当前反馈。
- 外键关联 `sessions` 和 `messages`，删除聊天时反馈自动清理。

问题文本和导师回答不重复复制，而是在查询时通过 `parent_message_id` 关联原消息。

对应代码：

- `backend/src/teachx/storage/database.py`
- `backend/src/teachx/storage/repository.py`

## 权限边界

保存反馈前，后端会检查：

```text
message_id 是否存在
→ 消息角色是否为 assistant
→ 消息所属会话的 user_id 是否等于当前用户
```

删除和列表查询同样带 `user_id` 条件。普通用户不能通过猜 `message_id` 给别人的回答
创建反馈，也不能删除别人的记录。

认证关闭时，本地开发用户为空 `user_id`，后端沿用项目的单用户模式，允许访问本地数据。

## 后端接口

当前提供四个接口：

```text
GET    /api/learning/feedback?session_id=...
GET    /api/learning/records
PUT    /api/learning/feedback/{message_id}
DELETE /api/learning/records/{feedback_id}
```

保存或更新反馈：

```json
{
  "rating": "wrong",
  "note": "我把特征向量和特征值混为一谈了。"
}
```

返回记录包含：

```text
原问题
导师回答
会话标题
反馈类型
学习者写下的误区
更新时间
```

因此记录页不需要再为每条反馈单独请求原消息。

## 聊天页中的三个动作

每条已经完成的导师回答下方会出现三个反馈按钮：

```text
有帮助
不清楚
记录我的误区
```

前两项点击后直接保存，再次点击同一个选项会取消。

“记录我的误区”会展开一个编辑框。只有填写内容后才能保存。保存后，误区会直接显示
在回答下方，并提供编辑和删除操作。

前端接口模块：

```text
frontend/lib/answer-feedback-api.ts
```

反馈按钮组件：

```text
frontend/features/chat/messages/AnswerFeedbackActions.tsx
```

## 学习记录页

页面地址：

```text
/learning-records
```

页面支持：

- 查看全部记录。
- 按“有帮助”“不清楚”“我的误区”筛选。
- 查看原问题、导师回答和误区内容。
- 打开原对话。
- 删除记录。
- 把误区带回聊天继续追问。

侧边栏增加了“学习记录”入口，因此它不是隐藏页面。

## “再弄懂一次”怎样把误区带回聊天

点击后不能只跳转到一个空聊天页。U4 使用现有 workspace draft 机制：

```text
记录页写入 /chat 的未发送草稿
→ 跳转 /chat
→ 聊天输入框恢复草稿
→ 用户确认后自己发送
```

没有自动发送，原因是：

- 用户应先看到生成的追问内容。
- 用户可以补充上下文或修改措辞。
- 避免页面点击直接触发一次模型费用和请求。

提示词会要求模型先提出一个诊断问题，再换一种方式解释，而不是简单重复原答案。

## 当前边界

- “错误”不是系统自动判定答案是否正确，而是用户主动标记的理解误区。
- 记录不会自动注入每一轮后续提示词，只有用户选择“再弄懂一次”时才带入。
- 当前没有掌握度、复习间隔和题目正确率，这些属于后续 U5。
- 记录页展示的是同一份用户数据，不做公开分享或管理员分析。
