# TeachX 技术教程

这套教程面向"学过 Python 基础语法，但还没读过工程项目"的读者。它不要求
你一开始就懂所有代码，而是沿项目本身的逻辑分层，一层一层把一个真实的
AI 学习助手搭出来。

## 学习地图：按项目的逻辑分层

TeachX 的代码天然分八层。教程按同样的顺序分组——**项目的架构图，就是
你的学习目录**：

```text
┌ 深度主线(P0~P3): 意图路由 · 端到端评测 · 记忆与监控
│   ↑ 建立在以下所有层之上,是项目的"现在"
├ 评测与可观测: 考卷化评测 · 回合 trace
│   ↑ 保障层:任何改动都被考卷拦着
├ 稳定性工程: 重试 · 幂等 · 并发 · 超时
│   ↑ Agent 敢接真实模型的前提
├ 模型接入与费用: 多平台连接 · token 与预算
│   ↑ 真实模型的入口
├ 用户与学习闭环: 认证隔离 · 档案/引导/错题/练习/目标
│   ↑ 产品的价值层
├ 知识与检索: RAG · 向量 · trigram · 查询扩写
│   ↑ "根据资料回答"的来源
└ Agent 核心: 流式输出 · 工具调用 · 上下文压缩 · MCP
    ← 一切的地基
```

## 三种读法

```text
新手顺序路线(约一周): 00 → 01 → 02 → 03 → 04 → 06 → 10 → 19
                      → 22 → 25 → 26 → 28,其余按需
面试冲刺路线(一两天): 每站挑一篇 ★——01/03/10/19/22/27/25/26/28,
                      读完每篇的"面试问答"并能复述
按需查阅:            改哪层读哪层,索引即架构图
```

标 ★ 的是对应层次最新的参考标准（写作风格、验证方式、面试问答深度
都以此为范本）。

## 学习方法

编写或修改教程前，请先阅读 [TeachX 文档写作指南](../规范/文档写作指南.md)。
教程需要让基础一般的读者知道"为什么、怎么做、结果是什么、出错怎么办"。
每篇大型功能教程还必须包含至少 8 个面试问答，解释设计动机、替代方案、
失败模式和工程取舍；教程 25~28 是当前参考示例。

不要只读代码，按照下面的循环学习每一章：

```text
先读人话解释
→ 打开对应源码
→ 只追踪一条路径
→ 回答自测题
→ 修改一个小地方
→ 运行测试
```

看不懂某个类时，不要立刻搜索所有相关文件。先回答三个问题：

1. 谁创建了它？
2. 谁调用了它？
3. 它最终把数据交给了谁？

这三个问题通常比"这个类一共有多少方法"更重要。

## 阅读约定

- "模块"指一个拥有明确输入和输出的代码单元，可以是一个函数、类或文件。
- "接口"不只指函数签名，还包括调用顺序、错误方式和必要配置。
- "适配器"指把外部系统转换成项目内部统一接口的代码。
- 星号 `*` 出现在函数参数前时，表示它后面的参数必须使用关键字传递。
- 章节编号沿用创建顺序（即 git 历史），**学习顺序以上面的地图为准**；
  合并/新增章节时保持既有编号不变，避免破坏外部引用。
