# 12：聊天页个性化状态

## 这篇解决什么问题

后端已经会使用学习档案，但用户看不到系统当前采用什么设置。

这会产生几个疑问：

- 我的学习档案真的生效了吗？
- 当前回答使用了哪个年级和讲解风格？
- 如果我不想个性化，怎样快速关闭？

U2 的目标是在聊天输入框上方展示一个轻量状态条。

## 最终界面

启用且有档案时显示：

```text
个性化：大一 · 先例子后原理    编辑  关闭
```

关闭时显示：

```text
个性化已关闭    编辑  开启
```

没有档案时显示：

```text
完善学习档案以启用个性化    去设置
```

状态条放在 ChatComposer 上方，不修改输入框自身的复杂参数。

## 为什么单独做组件

原 ChatComposer 已经有大量 props，直接继续增加状态和网络请求会让组件更难维护。

TeachX 新增：

```text
frontend/components/chat/home/PersonalizationStatus.tsx
```

它只负责：

- 查询认证状态。
- 查询个性化状态。
- 显示摘要。
- 快速开启或关闭。
- 跳转个人主页。

ChatWorkspace 只需要插入：

```tsx
<PersonalizationStatus />
```

这是一个小而独立的用户界面模块。

## 后端状态接口

```text
GET /api/auth/personalization
```

返回：

```json
{
  "available": true,
  "enabled": true,
  "learner_profile": {
    "grade_level": "大一",
    "explanation_style": "先例子后原理"
  }
}
```

- `available`：是否有可用的学习档案。
- `enabled`：用户是否开启个性化。
- `learner_profile`：用于生成摘要的档案数据。

## 为什么快速开关也调用同一个 PUT 接口

前端已有：

```text
PUT /api/auth/profile
```

请求：

```json
{
  "personalization_enabled": false
}
```

因此不需要再创建一套只用于聊天的设置接口。

## 设置何时生效

AgentRuntime 每个回合都会读取最新用户记录：

```python
current_user = await self.auth.get_user(user_id)
```

所以：

```text
在页面关闭个性化
→ 下一回合发送时后端重新读取
→ 下一回合不再注入档案
```

不需要重新建立 WebSocket 连接。

## 为什么不只依赖前端状态

前端状态条用于体验展示。真正是否使用档案仍由后端决定。

即使攻击者伪造：

```json
{"enabled": true}
```

后端仍读取数据库中的真实 `personalization_enabled` 值。

前端展示状态和后端权限判断必须分开。

## 认证关闭时怎么办

PersonalizationStatus 会先调用：

```text
/api/auth/status
```

如果认证未启用或用户未登录，组件直接返回 `null`，不显示状态条。

这样单用户本地开发界面不会被额外元素干扰。

## 摘要怎样生成

当前使用两个字段：

```tsx
[profile.grade_level, profile.explanation_style]
  .filter(Boolean)
  .join(" · ")
```

例如：

```text
大一 · 先例子后原理
```

如果没有这两个字段，可以在后续扩展：

- 阅读水平
- 偏好语言
- 课程体系

## 错误处理

状态接口失败时：

- 不阻塞聊天输入。
- 状态条隐藏。
- 不显示错误弹窗。

个性化是辅助体验，不应让聊天主流程无法使用。

快速开关失败时：

- 保留原状态。
- 恢复 busy 状态。
- 后续可增加 toast 提示。

## 测试方法

浏览器验证步骤：

1. 登录并完善学习档案。
2. 打开 `/chat`。
3. 检查状态条显示年级和讲解风格。
4. 点击“关闭”。
5. 确认状态变为“个性化已关闭”。
6. 点击“开启”。
7. 确认摘要恢复。

后端测试还会验证：

- `/api/auth/personalization` 返回正确状态。
- 学习档案字段完整。
- 个性化开关持久化。

## 常见误区

### “状态条只是装饰”

它同时提供快速控制入口，避免用户每次去个人主页修改。

### “关闭后当前正在生成的回答会变”

不会。设置从下一回合生效，已经开始的回合保持原输入。

### “需要重新连接 WebSocket”

不需要。后端每回合重新读取用户设置。

### “状态条失败时聊天也不能用”

不应该这样。辅助功能失败不应阻塞主流程。

## 小练习

5. 在回答完成事件中显示 `personalization_applied`。
