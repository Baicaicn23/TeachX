# 17：用户模型连接与多平台

## 这一章解决什么问题

后端环境变量只能提供一个全局默认模型。真实产品还需要让用户自己选择：

- TeachX 平台默认模型。
- DeepSeek。
- OpenAI。
- 其他兼容 OpenAI Chat Completions 和 `/models` 的平台。

U7 增加“模型连接”入口。用户保存自己的 Base URL、API Key 和默认模型，并在聊天时按
当前账号选择要使用的 Provider。

## 两层模型配置

系统现在有两层配置。

### 平台默认

由后端环境变量或本地 `backend/.env` 决定：

```text
TEACHX_LLM_PROVIDER=openai
OPENAI_API_KEY=...
OPENAI_BASE_URL=https://api.deepseek.com/v1
TEACHX_MODEL=deepseek-flash
```

没有个人激活连接时，所有聊天使用平台默认。

### 用户连接

保存在 SQLite 的 `model_connections` 表，按 `user_id` 隔离：

```text
name
base_url
api_key_encrypted
default_model
models
active
```

用户可以在多个连接之间切换，也可以选择“使用平台默认”取消个人覆盖。

## API Key 怎样保护

API Key 不直接明文保存。服务使用 `TEACHX_AUTH_SECRET` 派生 Fernet 密钥，再加密后
写入数据库。

API 响应只返回：

```text
has_api_key: true
```

不会返回明文 Key，也不会返回密文。编辑连接时如果 Key 输入框留空，后端保留原有 Key。

注意：修改 `TEACHX_AUTH_SECRET` 会导致旧连接无法解密，用户需要重新填写 Key。

## 测试连接和选择模型

“测试连接”会调用：

```text
GET {base_url}/models
```

成功后返回模型 ID 列表。例如 DeepSeek 当前返回：

```text
deepseek-flash
deepseek-v4-pro
```

用户可以从中选择默认模型。自定义平台即使不提供 `/models`，也可以直接填写一个已知
模型 ID 保存连接；但“测试连接”需要平台实现标准模型列表接口。

## 后端接口

```text
GET    /api/model-connections
POST   /api/model-connections
POST   /api/model-connections/test
POST   /api/model-connections/default/activate
POST   /api/model-connections/{connection_id}/activate
DELETE /api/model-connections/{connection_id}
```

列表响应区分：

```text
platform_default
connections
```

个人连接包含名称、Base URL、模型列表和是否激活，不包含 API Key。

## 聊天时怎样选择 Provider

WebSocket 每个回合开始前：

```text
user_id
→ 查询该用户 active 的 model_connection
→ 解密 API Key
→ 创建 OpenAICompatibleProvider
→ 传给 AgentRuntime.run_turn(provider=...)
```

没有个人连接时：

```text
provider = None
→ AgentRuntime 使用平台默认 Provider
```

AgentRuntime 的 Agent Loop、工具调用和事件协议没有变化，只替换 Provider 实例。

## 前端入口

页面地址：

```text
/model-connections
```

侧边栏提供“模型连接”入口。页面支持：

- DeepSeek、OpenAI 和自定义 OpenAI 兼容平台预设。
- 测试连接并读取模型列表。
- 设置连接名称、Base URL、API Key 和默认模型。
- 保存、编辑、删除和激活连接。
- 切回 TeachX 平台默认。

## 真实 DeepSeek Flash 验证

本次使用真实 DeepSeek 凭据验证：

```text
/models
→ deepseek-flash
→ deepseek-v4-pro

流式文本
→ 6 个内容片段
→ finish_reason = stop

工具调用
→ calculator
→ {"expression": "19 * 23"}

浏览器
→ 保存并激活 DeepSeek Flash
→ 真实聊天返回“真实模型连接成功”
→ 不再出现 Mock 固定回答
→ API 响应不包含用户 Key
```

## 自动测试安全

本地 `backend/.env` 可能指向真实付费 API。`scripts/check.sh` 会强制测试使用：

```text
TEACHX_LLM_PROVIDER=mock
TEACHX_EMBEDDING_PROVIDER=mock
```

因此普通自动测试不会消耗 API 额度，也不会因为网络波动而失败。真实联调单独执行。

## 当前边界

- 只支持 Chat Completions 形态，不直接支持只提供 Responses API 的平台。
- 模型列表接口必须兼容 OpenAI `/models`。
- 个人连接目前只影响聊天 Provider，不影响 Embedding；向量检索仍使用平台配置。
- 用户 Key 已加密存储，但生产环境仍应配合磁盘加密、密钥托管和审计。
- 管理员不能查看普通用户保存的明文 Key。
