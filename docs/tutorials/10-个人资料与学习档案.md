# 10：个人资料与学习档案

## 为什么要做用户资料

同一个问题，不同用户需要不同回答方式：

- 小学生需要更多比喻和更短句子。
- 高中生需要知识框架和考试表达。
- 成年人可能只需要结论和参考资料。

如果所有用户共用同一套系统提示词，AI 很难长期贴合个人需求。

TeachX 因此把用户信息拆成两类：

```text
账户资料
→ 用户名、角色、创建时间、头像

学习档案
→ 年龄、年级、课程体系、语言、阅读水平、讲解风格
```

## 账户资料

接口：

```text
GET /api/auth/profile
PUT /api/auth/profile
```

`GET` 返回：

```json
{
  "id": "user-id",
  "username": "learner@example.com",
  "role": "user",
  "created_at": "2026-10-01T...",
  "avatar": "icon:star:violet"
}
```

`created_at` 使用 ISO 8601 字符串，方便 JavaScript：

```javascript
new Date(profile.created_at)
```

## 头像的两种形式

### 图标头像

格式：

```text
icon:<图标名>:<颜色名>
```

例如：

```text
icon:star:violet
```

它只保存很小的字符串，不产生图片文件。

### 图片头像

格式：

```text
img:<版本号>
```

例如：

```text
img:1790867000123
```

版本号用于让浏览器在头像更换后立即刷新缓存。

图片本身保存在：

```text
data/avatars/<user-id>.<extension>
```

数据库不保存大块二进制数据。

## 为什么要验证图片格式

不能只相信文件扩展名或浏览器传来的 MIME 类型。

服务端会检查文件头：

- PNG：`\x89PNG`
- JPEG：`\xff\xd8\xff`
- WebP：`RIFF....WEBP`

同时限制图片最大为 1 MB。

前端负责裁剪和压缩，后端负责最终安全校验。

## 学习档案

接口：

```text
GET /api/auth/profile/learner-profile
PUT /api/auth/profile/learner-profile
```

字段：

```json
{
  "age": 19,
  "grade_level": "大一",
  "curriculum": "计算机",
  "language": "中文",
  "reading_level": "入门",
  "explanation_style": "先例子后原理"
}
```

后端使用 Pydantic 校验：

- 年龄必须在 3 到 120 之间。
- 文本字段有长度上限。
- 未填写的字段不会保存。

## 为什么使用 JSON 存储学习档案

学习档案字段会持续变化：

- 以后可能增加学习目标。
- 可能增加每周学习时间。
- 可能增加学科偏好。

如果每个字段都建一列，迁移会越来越频繁。当前数据量小、无需复杂查询，因此使用 JSON：

```sql
users.learner_profile TEXT
```

如果未来需要按年级统计，可以再迁移为独立列或单独表。

这是有意的设计选择，不是“偷懒式字符串拼接”。

## Pydantic 验证

接口模型：

```python
class LearnerProfileUpdate(BaseModel):
    age: int | None = Field(default=None, ge=3, le=120)
    grade_level: str | None = Field(default=None, max_length=64)
```

如果传入：

```json
{"age": 999}
```

FastAPI 会在进入业务层之前返回 422，避免非法数据写入数据库。

## 前端页面

用户直接从个人主页编辑：

```text
/profile
```

页面包含：

- 账户信息。
- 头像上传或图标选择。
- 学习档案表单。
- 保存状态。
- 退出登录。

保存成功后显示：

```text
已保存
```

## 隐私原则

默认情况下，学习档案只属于当前用户。

需要注意：

- 不把学习档案展示给其他普通用户。
- 管理员若后续需要查看，必须有明确权限和审计。
- AI 提示词中只注入当前请求需要的字段。
- 用户应该知道哪些资料会被用于个性化。

## 常见误区

### “头像就是用户名首字母”

首字母可以是没有图片时的兜底，但正式头像应允许用户选择图标或上传图片。

### “前端已经裁剪，所以后端不用验证”

错误。攻击者可以绕过前端直接请求 API。

### “学习档案可以无限增加字段”

不会。字段越多，隐私和提示词注入风险越大，应保持最小必要。

### “保存到 JSON 就不需要校验”

JSON 只是存储方式，不代替 Pydantic 校验和权限检查。
