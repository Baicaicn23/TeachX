# 29：从错题出题

> 本章适合第一次接触"把数据变成练习材料"的读者。读完后你能说清：
> 学生随手记下的一条误区，是怎么变成一道新练习题的；以及为了让这条路走通，
> 我们改了数据库、改了权限、踩了哪些坑。

## 为什么需要它

学生在这个产品里会做一件事：在导师的回答下面点"**记录我的误区**"，写一句
"我把定积分和不定积分的结果类型搞混了"。

这句话记下来之后呢？**原来它哪儿也没去。** 它躺在"学习记录"页里，能看、能删、
能带回聊天，但**没有任何一个地方拿它出过题**。

而"练习"原来只有一种做法，而且很笨：

```text
从知识库里抠出一段话 → 套一句固定的话 → 变成一道题

"请用自己的话解释下面这段资料。回答时说明核心概念、关键关系和一个具体例子。
 资料摘录：\n「……」。"
```

它确定、零成本、可测试，但有两个问题：

1. **不像题。** 它只是"把这段资料复述一遍"，不是针对某个知识点的练习。
2. **用不上错题。** 学生亲手标记的薄弱点——最有价值的信号——完全没被利用。

这一章做的事就是：**让记下来的错题自己长出练习题。**

## 最终结果

三个地方会有变化：

| 位置 | 你会看到什么 |
| --- | --- |
| 练习页 | 多一个"**出题来源**"选择器：`来自知识库` / `来自我的错题` |
| 练习页（选错题） | 生成一道**新的**题，考同一个知识点；题卡上带"**来自你的误区**"标签 |
| 学习记录页 | 每条误区旁边多一个按钮：**「用它出练习题」** |
| 聊天框 | 说"根据我的知识库出几道题"，练习 agent **能翻资料**了（原来它会说"我看不到你的知识库"） |

## 前置条件

- 后端能跑（`./scripts/dev.sh`）
- 至少有一个知识库，里面有点资料
- 至少记录过一条误区（在任意一条导师回答下面点"记录我的误区"并写一句话）
- **`.env` 里要有 `TEACHX_MAX_OUTPUT_TOKENS=4096`** —— 这一条很重要，
  理由见下面的"踩坑"一节

## 操作步骤

### 1. 记一条误区

在主页问一道题，然后在回答下方点 **"记录我的误区"**，写下你的理解偏差。

> **预期**：侧边栏 → 学习记录，能看到这条记录。

### 2. 从错题出题

到侧边栏 → **练习** → 把"出题来源"切成 **「来自我的错题」** → 点生成。

或者更快：直接在学习记录里点那条误区旁的 **「用它出练习题」**。

> **预期**：出现一道新题，题卡上方有"**来自你的误区**"标签。题目内容应该
> **正好打在你的误会上**，而且换个问法、换组数字——不是把原题抄一遍。

### 3. 观察"只出一次"

再点一次生成。

> **预期**：提示"还没有可用于出题的新错题"。**同一条误区只会出一次题**，
> 不会因为你多点几次就堆出一堆重复题。

## 它是怎么工作的

```text
① 学生点"记录我的误区"
   → 错题落库，并记下"这是哪个知识库下的问题"      ← 学科继承
        ↓
② 学生选"来自我的错题" → 点生成
   → 找出还没出过题的误区（按学科筛选可选）
        ↓
③ 每条误区交给模型："针对这个误区出一道新题"
   → 模型返回一道题；返回不了就用模板兜底          ← 模型写题 + 模板回退
        ↓
④ 新题落库，挂在误区所属学科下，并标记"来自哪条误区"
   → 靠这个标记去重                                ← 一条误区只出一题
```

拆开看三件事。

### 学科继承：错题必须知道自己属于哪个学科

数据库里有一条硬规定：**练习题必须挂在某个知识库下**（题目表的
`knowledge_base` 是必填的）。而"错题"原来**根本没记学科**——它只知道自己
关联着哪个会话、哪条消息。

所以第一步是让错题带上学科。学科从哪来？**学生提问那一刻正好选了知识库**。
所以导师回答的元数据里补记一笔"本轮选了哪些库"，错题创建时取第一个。

> 这个做法有先例：长期记忆的学科标签是同一个口径（取本轮第一个知识库）。
> 两处保持一致，就不会出现"记忆说你在学线代、错题说你在学高数"这种事。

**没有学科的错题怎么办？** 出不了题，直接跳过。聊天时没选知识库的提问就是
这种情况——它本来也没有资料可依托。

### 模型写题：写不出来要能退回老办法

出题这一步新加了一层"让模型写题"：

```text
把误区交给模型 → 要求它返回 {"question": "题目正文"}
→ 解析成功:用模型的题
→ 解析失败/模型不可用/预算超限:用原来的模板拼一道题
```

**关键约定：出题永远不会因为模型出问题而失败。** 拿不到模型就用模板出一道
"你之前在这一块卡过…重新独立做一遍"，虽然不如模型写的贴切，但**题还是有的**。

这套"两层"的写法在项目里不是第一次出现——意图识别也是这么做的（规则兜底 +
模型复核，模型失败就回退规则）。同一个模式复用三处，读代码的人只需要理解一次。

**什么情况下会走模板？**

| 情况 | 结果 |
| --- | --- |
| 没配模型 / 跑在 Mock 模式 | 模板出题 |
| 当日预算已用完 | 模板出题 |
| 模型调用失败（网络、限流） | 模板出题 |
| 模型返回的东西解析不出题目 | 模板出题 |

每一种都会**在服务端日志里留一行**，不会静默退化。

### 去重：一条误区只出一道题

练习题表有一个"这条题来自哪条误区"的字段，配一个**部分唯一索引**
（只管来自误区的那些行，来自知识库的行不受约束）。同一条误区第二次出题时，
数据库层面就插不进去，服务层直接告诉用户"没有新的错题了"。

## 踩坑：模型返回了空内容

这个功能第一次真机验证时，生成的题是**模板题**，不是模型写的。模型调用的
记录里也一条都没有——看起来像"模型根本没被调用"。

加日志之后真相是：

```text
[practice] 模型返回无法解析,改用模板: ''
```

模型**被调用了，但返回了空字符串**。原因是我们给这次调用硬压了一个很小的
输出上限（512 token），而 `deepseek-flash` 是**推理型模型**——它会把输出预算
先花在"思考"上，512 全烧完，留给正文的是零。

改成**不覆盖上限、用配置里的值**（4096）之后，一次就正常了。

这个坑在项目里出现过两次（另一次见教程 26 的 `output_truncated`），教训是：
**给推理模型设置输出上限时，要留出思考的余量；能交给配置就别在调用点写死。**

另外还踩了一个同类坑：`except Exception` 把"容器里少了依赖"这种**配置错误**
一起吞掉了，表现成"功能不生效"而不是"报错"。所以现在这两处回退路径都会打印
一行日志——**降级可以，静默降级不行**。

## 顺带改的一件事：练习 agent 从"没有工具"变成"能读不能写"

原来练习子 agent 是**一个工具都不给**的，理由是"做题不该翻书"。结果学生选了
知识库说"根据我的资料出题"，它只能回答"我看不到你的知识库"——**功能等于做废**。

现在改成**只读**：

| 子 agent | 权限 |
| --- | --- |
| `progress` | 一个工具都不给（`deny_all`） |
| `practice` | **只读**：能检索资料，写入工具进黑名单 |
| `tutor` / `retriever` / `chat` | 能读也能写（可以帮你沉淀题目） |

**一个必须记住的细节**：只把写入工具从"默认工具集"里去掉**是不够的**。
用户显式勾选的工具不会被默认集推翻——必须把它放进**黑名单**，执行层才拦得住。

所以"出题不改动你的数据"这句话，现在是在**执行层**成立的产品承诺，不是提示词
里的劝告。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 生成的题是"你之前在这一块卡过…" | 走的是**模板**，不是模型 | 看后端日志有没有 `[practice]` 开头的行；确认 `.env` 里 `TEACHX_MAX_OUTPUT_TOKENS=4096` |
| 提示"还没有可用于出题的新错题" | 没有误区，或误区都出过题了，或**误区没有学科** | 先记录一条误区；如果是老数据（记于本功能之前），学科是空的，需要重新记一条 |
| 题目的学科不对 | 记误区时的知识库选择与预期不符 | 学科取自**记误区那一刻**当轮所选的知识库 |
| 学习记录里没有"用它出练习题"按钮 | 该记录的评分不是"误区" | 按钮只对 `rating = wrong` 且写了备注的记录显示 |

## 当前边界

- **模板回退的题比较套话。** 没模型时能出题，但不如模型写的贴切。
- **学科取自第一个知识库。** 一次选了多个库提问时，只看第一个。
- **老数据没有学科。** 本功能上线前记的误区学科为空，出不了题。
- **误区类型只认 `wrong`。** "回答不清楚"（`unclear`）不参与出题。
- **学习记录里的"用它出练习题"跳转到练习页的错题模式**，不是只出那一条——
  生成时取的是"最新的、还没出过题的"几条。
- **出题会花钱。** 每出一次题就是一次模型调用；预算超限时自动退回模板。

## 面试问答

**1. 这个功能解决了什么问题？**
把学生亲手标记的薄弱点变成练习材料。原来的出题只会"抠一段资料让他复述"，
学生记的误区完全没被利用；现在错题会自己长出针对同一知识点的新题。

**2. 为什么练习题必须挂在知识库下？错题没有学科不就出不了题了吗？**
因为产品里"掌握度""复习排期"都是按学科聚合的——一道题不归任何学科，它在
进度视图里就没有位置。所以我们没去改这个约束，而是**给错题补上学科**：
学生提问那一刻正好选了知识库，这个信息是现成的，只是原来没记下来。

**3. 为什么让模型写题，而不是继续用模板？**
模板出的是"复述资料"，不是练习题；而且它没法利用误区——模板里塞一句
"你之前卡过"就完了，出不来一道**针对那个知识点、换个角度**的题。
代价是出题开始花钱，所以做了模板兜底和预算闸。

**4. 模型出题失败了会怎样？**
退回模板，题目照样有。整个出题**不会因为模型的问题而失败**。这是刻意的：
出题是用户主动发起的动作，失败一次就是一次糟糕体验。判断失败的标准包括
"返回空内容"和"解析不出 JSON"——两者都见过了，都能兜住。

**5. 为什么那次模型返回空内容？**
给这次调用写死了 512 的输出上限，而模型是推理型的，把预算全花在思考上，
正文一个字不剩。改成用配置里的值（4096）就好了。教训是**给推理模型留思考
余量，能交给配置就别在调用点写死**。

**6. 为什么用"静默回退"不好？**
因为"功能不生效"和"功能报错"的排查难度差一个数量级。那次空内容，如果没有
日志，只能看到"生成的题是模板题"，完全没有线索。所以现在每条回退路径都会
打印一行。**降级可以，静默降级不行。**

**7. 练习 agent 为什么要改成"能读不能写"？原来的最小权限不是讲点吗？**
原来的"一个工具都不给"把功能做废了——学生选了资料让它出题，它答"我看不到
你的知识库"。改成只读之后，那条真正的产品承诺反而更清楚了：**出题能看你的
资料，但不会改动你的数据**。而且同一个路由表里有三种权限档位（全禁 / 只读 /
读写），比"一刀切不给"更能体现最小权限。

**8. 为什么写入工具要进黑名单，不能只从默认工具集里去掉？**
因为**用户显式勾选的工具不会被默认集推翻**。只改默认集，用户自己勾一下就把
写权限拿回来了——那这句承诺就不成立。放进黑名单，schema 层看不见、执行层也
拦得住。

**9. 同一条误区会不会重复出题？**
不会。练习题表记了"来自哪条误区"，配一个部分唯一索引（只管来自误区的行）。
第二条插不进去，服务层直接回"没有新的错题了"。

**10. 这个功能的可测试性怎么样？**
分层测。提示词拼装和解析是纯函数，直接单测（含代码块、坏 JSON、敷衍输出）；
服务层用 Mock Provider 测"模型路径"和"模板回退"两条分支；权限改动由任务级
考卷在真实回合里断言。全部零 API 消耗。
