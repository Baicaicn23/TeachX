# 03：工具调用是怎么工作的

## 先用人话理解

模型擅长理解和生成语言，但不擅长可靠地算数、访问本地数据或执行操作系统任务。

工具调用相当于给模型一张“可调用服务菜单”：

```text
计算器：输入 expression，返回结果
知识库搜索：输入 query，返回片段
当前时间：不需要参数，返回时间
```

模型看到菜单后，可以选择调用哪个工具，并生成符合格式的参数。

## 工具的定义

工具基类位于：

```text
backend/src/teachx/runtime/tools.py
```

每个工具必须声明：

```python
name = "calculator"
description = "Evaluate a basic arithmetic expression safely."
parameters = {...}
```

`parameters` 使用 JSON Schema 描述输入格式。模型会根据它生成参数。

## 给模型看的不是 Python 函数

Provider 收到的是结构化 schema：

```json
{
  "type": "function",
  "function": {
    "name": "calculator",
    "description": "Evaluate a basic arithmetic expression safely.",
    "parameters": {
      "type": "object",
      "properties": {
        "expression": {"type": "string"}
      },
      "required": ["expression"]
    }
  }
}
```

模型不会直接执行 Python。它只返回“我想调用 `calculator`，参数是
`{\"expression\": \"12 * 8\"}`”。

## 第一次模型调用

用户输入：

```text
计算 12 * 8
```

Provider 返回：

```python
LLMResult(
    content="",
    tool_calls=[
        ToolCall(
            id="call-1",
            name="calculator",
            arguments={"expression": "12 * 8"},
        )
    ],
)
```

AgentRuntime 看到 `tool_calls` 不为空，就知道这一轮不能结束。

## 执行工具

AgentRuntime 调用：

```python
tool_result = await self.tools.execute(
    call.name,
    call.arguments,
)
```

ToolRegistry 根据名称找到 CalculatorTool，执行安全 AST 计算，返回：

```python
ToolResult(content="96", success=True)
```

这里也体现了适配器的价值：AgentRuntime 不需要知道计算器内部如何解析表达式。

## 把工具结果送回模型

工具结果必须变成一条 `tool` 消息：

```python
{
    "role": "tool",
    "tool_call_id": "call-1",
    "name": "calculator",
    "content": "96",
}
```

`tool_call_id` 非常重要，它告诉模型“这个结果对应刚才哪一次调用”。

## 第二次模型调用

消息列表现在包含：

```text
system：导师规则
user：计算 12 * 8
assistant：请求调用 calculator
tool：96
```

模型第二次调用时，会基于 `96` 生成面向用户的解释，而不是重复请求工具。

## Agent Loop 为什么需要循环

一次完整流程可能是：

```text
第 1 轮：模型请求计算器
→ 执行工具
第 2 轮：模型认为还需要查知识库
→ 执行工具
第 3 轮：模型获得足够信息，生成最终回答
```

因为工具调用次数不固定，所以需要循环。

项目设置了 `max_rounds`。当轮数超过上限时，系统会停止，避免模型无限调用工具。

## 事件如何展示给前端

工具调用会产生两个事件：

```json
{"type": "tool_call", "content": "调用工具：calculator"}
{"type": "tool_result", "content": "96"}
```

P1 又加入了：

- `call_id`：配对调用和结果。
- `call_state`：`running` 或 `complete`。
- `duration_ms`：工具执行耗时。
- `success`：是否成功。

这些字段让前端可以绘制更完整的执行轨迹。

## 为什么不能让模型直接执行任意 Python

如果模型生成 `__import__("os").system(...)` 并被执行，会产生严重安全问题。

当前 CalculatorTool 只允许：

- 数字常量
- `+ - * / % **`
- 一元正负号
- 括号形成的 AST 结构

任何函数调用、属性访问和导入都会报错。

## 常见误区

### “模型调用了工具，工具就自动执行”

不会。模型只提出调用请求，必须由后端 ToolRegistry 验证并执行。

### “工具返回内容会直接给用户”

不一定。工具内容是给模型继续推理的，最终是否展示由 Runtime 和前端事件决定。

### “工具越多越好”

工具越多，模型选择越困难，提示词和权限控制也越复杂。应该先增加高价值工具。
