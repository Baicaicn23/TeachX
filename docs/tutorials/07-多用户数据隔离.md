# 07：多用户数据隔离

## 为什么登录后还需要数据隔离

只要求用户登录，不能保证数据安全。

如果没有隔离，用户 A 登录后仍然可以通过接口读取用户 B 的会话或知识库：

```text
用户 A 已登录 → 有权限使用系统
用户 A 读取用户 B 的资料 → 不应该允许
```

数据隔离要给每条业务数据回答一个问题：

```text
这条数据属于谁？
```

## 最基础的隔离方式：owner_id

TeachX 在会话和知识库表上记录所有者：

```sql
sessions.user_id

knowledge_bases.owner_id
```

创建数据时写入当前用户：

```python
await knowledge.create_base(
    name,
    owner_id=user.id,
)
```

读取时增加所有权条件：

```sql
WHERE b.name = ?
  AND b.owner_id = ?
```

条件必须写进数据库查询，而不是只在前端过滤。

## 为什么不能相信前端

假设前端只显示用户自己的知识库，但后端详情接口没有检查所有权：

```text
GET /api/knowledge-bases/别人的知识库
```

攻击者可以直接构造请求，完全绕过界面按钮。

正确边界是：

```text
浏览器可以做体验过滤
后端必须做最终授权
```

## KnowledgeService 如何处理权限

`KnowledgeService` 的方法接收：

```python
owner_id: str = ""
is_admin: bool = False
```

规则：

```text
owner_id 为空
→ 单用户本地模式，不额外过滤

owner_id 有值且不是管理员
→ 只能访问 owner_id = 当前用户 的数据

owner_id 有值且是管理员
→ 可以访问全部数据
```

核心过滤条件在：

```python
def _owner_filter(alias, owner_id, is_admin):
    if not owner_id or is_admin:
        return "", ()
    return f"AND {alias}.owner_id = ?", (owner_id,)
```

## 为什么列表、详情和搜索都要过滤

只保护详情接口还不够。至少需要保护：

- 知识库列表。
- 知识库详情。
- 文件列表。
- 文件预览和下载。
- 上传文档。
- 删除知识库和文件。
- 关键词与向量检索。
- 向量重建。
- `knowledge_search` Agent 工具。

任何一条漏掉，都可能成为越权入口。

## Agent 工具也必须带用户身份

模型调用 `knowledge_search` 时，不是浏览器直接访问数据库。

调用链是：

```text
AgentRuntime
→ ToolContext
→ KnowledgeSearchTool
→ KnowledgeService
```

因此 `ToolContext` 保存：

```python
user_id
is_admin
```

检索工具把它继续传给 KnowledgeService：

```python
owner_id=context.user_id
is_admin=context.is_admin
```

这样模型拥有工具调用能力，也不能绕过用户边界。

## 会话隔离

会话使用相同的原则：

```sql
WHERE s.id = ?
  AND (? = '' OR s.user_id = ?)
```

认证关闭时用户 ID 为空，保持本地单用户开发体验。  
认证开启时，只返回当前用户自己的会话。

## 为什么管理员可以查看全部

管理员需要：

- 排查用户问题。
- 管理共享资源。
- 处理违规内容。
- 查看系统整体状态。

因此管理员是权限规则中的显式例外，不是“没有 owner_id 的用户”。

普通用户和管理员都必须通过后端 `require_user` 认证，只是在资源范围上不同。

## 常见误区

### “前端不显示就等于没有权限”

错误。隐藏按钮不构成安全边界。

### “知道知识库名字才能访问，所以没关系”

错误。知识库名可能被猜到、泄露或出现在链接中。

### “只在列表接口过滤就够了”

错误。详情、搜索、下载、删除和 Agent 工具都需要检查。

### “管理员不用认证”

错误。管理员权限更高，更必须认证和审计。

## 小练习

2. 设计共享知识库的授权表。
3. 为管理员访问知识库增加审计日志。
4. 写一个测试：用户二无法删除用户一的知识库。
5. 思考如果使用 PostgreSQL，权限条件应该放在 ORM 还是数据库行级安全策略中。
