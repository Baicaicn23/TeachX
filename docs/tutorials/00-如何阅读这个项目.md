# 00：如何阅读这个项目

## 这篇解决什么问题

很多初学者读项目时会从第一个文件开始，然后很快迷路。TeachX 的文件不少，
但真正需要先读懂的主路径只有一条：

```text
浏览器
→ Next.js
→ WebSocket
→ FastAPI
→ AgentRuntime
→ Provider
→ Tool
→ SQLite
```

先理解这条路径，其他文件就会从“散落的代码”变成“主路径旁边的功能”。

## 先认识四个目录

### `frontend/`

这是用户在浏览器里看到的界面，使用 Next.js、React 和 TypeScript。

你暂时不需要学习全部前端代码。先知道两个位置即可：

- `frontend/app/`：页面在哪里。
- `frontend/features/chat/`：聊天功能的主要前端逻辑。

### `backend/`

这是 TeachX 自己开发的后端，使用 Python、FastAPI 和 Pydantic。

最重要的目录是：

```text
backend/src/teachx/
├── api/          HTTP 和 WebSocket 入口
├── providers/    模型适配器
├── runtime/      Agent Loop、提示词和工具
└── storage/      SQLite 持久化
```

### `docs/`

项目文档和教程。你当前正在阅读的内容也放在这里。

### `scripts/`

开发辅助脚本：

```bash
./scripts/dev.sh     # 同时启动前后端
./scripts/check.sh   # 运行检查
```

## Python 项目的阅读顺序

### 第一步：找入口

后端入口是：

```text
backend/src/teachx/main.py
```

这个文件创建 FastAPI 应用，并在应用启动时准备：

- 数据库
- Repository
- Provider
- Tool Registry
- AgentRuntime

可以先把它理解成“装配车间”。它负责把零件组装起来，不负责具体业务逻辑。

### 第二步：找外部请求入口

HTTP 和 WebSocket 路由在：

```text
backend/src/teachx/api/routes/
```

前端聊天使用 WebSocket，所以最先看：

```text
backend/src/teachx/api/routes/ws.py
```

### 第三步：找核心业务

核心业务在：

```text
backend/src/teachx/runtime/engine.py
```

这里负责一次完整回合：保存用户消息、调用模型、执行工具、流式发送结果、
保存助手消息。

### 第四步：找外部依赖的适配器

模型调用在：

```text
backend/src/teachx/providers/
```

数据库访问在：

```text
backend/src/teachx/storage/
```

## 如何启动项目

先启动后端：

```bash
cd backend
uv sync
uv run uvicorn teachx.main:app --app-dir src --reload --port 8010
```

再启动前端：

```bash
cd frontend
cp .env.example .env.local
npm ci
npm run dev
```

浏览器访问 `http://localhost:3000`。

默认使用 Mock 模型，不需要 API Key。输入：

```text
计算 12 * 8
```

如果页面正常显示工具调用和最终回答，说明主路径已经跑通。

## 理解 Python 文件时，先看什么

一个 `.py` 文件通常按下面的顺序阅读：

1. 顶部 `import`：它依赖谁。
2. `class` 声明：它代表什么对象。
3. `__init__`：创建对象时需要保存哪些状态。
4. 公开方法：别人怎样使用它。
5. 私有方法：内部怎样实现。
6. 数据类：数据在模块之间怎样传递。

例如 `AgentRuntime` 的 `run_turn()` 是公开入口，而 `_event()` 是内部辅助函数。

Python 约定以单下划线开头的名字表示“内部使用”。它不是强制安全限制，
而是在提醒调用者：不要把这个函数当成稳定的公共接口。

## 常见的两个阅读错误

### 错误一：从数据库开始读

数据库很重要，但它不是业务的起点。业务起点是用户消息进入 WebSocket。

### 错误二：试图记住所有代码

不需要记住实现。你只需要记住每个模块的职责和接口，需要时再回来看细节。

## 自测题

1. 为什么先从入口文件开始，而不是从工具类开始？
2. `providers/` 和 `runtime/` 的职责有什么区别？
3. 如果模型供应商更换了，最可能修改哪个目录？
4. 如果聊天消息保存格式改变了，最可能修改哪个目录？
