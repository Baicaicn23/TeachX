# 2026 AI 岗位技术栈调研

> 调研日期：2026-10-02
>
> 目的：判断 AI 应用、Agent、RAG、评测和 AI 平台岗位现在真正看重什么，
> 并据此调整 TeachX 的后续开发优先级。

## 先给结论

“LLM 流式调用”和“会接一个聊天 API”已经是基础能力，不再适合作为项目的主要亮点。
当前岗位反复出现的分水岭是：

```text
能不能把模型做成可靠、可评测、可观测、可控、可部署的系统
```

2026 年更有招聘价值的核心词是：

- Agent Harness / Agent Runtime
- Evaluation / Evals
- Observability / Tracing
- Context Engineering
- Memory
- Tool Orchestration / Tool Permissions
- Human-in-the-loop
- Model Routing
- Reliability / Idempotency / Durable Workflows
- Retrieval / Reranking
- Sandbox / Execution Isolation
- MCP，以及仍处于早期阶段的 A2A
- Latency、Cost、Production System

数据库、向量库和框架名称仍然有用，但它们更像实现细节。公司更关心候选人是否能解释
为什么选它、怎么评测、怎么保证权限和稳定性，以及如何从真实失败数据中持续改进。

## 调研方法

本次没有只参考教程和自媒体，而是组合了三类证据：

1. 当前官方招聘职位描述。
2. 主流协议、工程指南和安全标准。
3. 国内团队开源产品体现出的技术方向。

样本不是全网统计，不能代表所有公司；它更适合用于识别共同趋势，而不是给技术栈排名。

## 一、官方职位描述释放了什么信号

### Anthropic：Applied AI Engineer

职责强调为企业构建生产级 LLM 方案、架构集成、定制原型和 evaluation suites。
Preferred qualifications 明确写有“近期构建生产 LLM 系统”的经验。

来源：[Applied AI Engineer](https://job-boards.greenhouse.io/anthropic/jobs/5390799008)

关键词：

```text
production LLM systems
system architecture
evaluation suites
reliability
safety
```

### Scale AI：Frontier Agents Engineer

职位把 Agent 能力拆得非常清楚：reasoning、retrieval、memory、tool use、multi-agent、
human oversight。并要求完整实验生命周期，包括 golden datasets、regression suites、
LLM-as-a-Judge、human evaluation、A/B experiments 和 ablation studies。

来源：[Frontier Agents Engineer (Applied AI)](https://job-boards.greenhouse.io/scaleai/jobs/4720573005)

这是本次调研最完整的岗位描述之一。它说明 Agent 项目只看“能调用工具”远远不够，
还要能科学地证明模型、提示词、检索、记忆和架构改动到底有没有效果。

### Sierra：Agent Runtime

职责包括 Agent SDK、orchestration engine、runtime、knowledge retrieval，以及让
客户可以持续测量和改进 Agent quality 的框架。

来源：[Software Engineer, Agent Runtime](https://jobs.ashbyhq.com/sierra/b3829801-8e0b-4047-8cd8-8a51c87028fd)

### LangChain：Agent Reliability Engineer

职位明确描述平台包含 Observability、Evaluation、Deployment、Fleet 和 Sandboxes，
并使用 LangGraph、DeepAgents、LangSmith、Supabase Postgres、BigQuery 构建和运营
生产 Agent。

来源：[Agent Reliability Engineer](https://jobs.ashbyhq.com/langchain/eadd2a71-47fc-483b-948f-4b2384f7f93f)

这里值得学的不是特定品牌，而是“构建平台—在生产中使用平台—用真实数据改进平台”的闭环。

### Cursor：Agent Evaluation and Quality

岗位要求建设：

- curated datasets。
- offline replay。
- scorers / judges。
- regression alerts。
- dashboards。
- real usage feedback loop。
- failure mode clustering。
- “good / bad / degraded” session 定义、告警和分诊。

来源：[Agent Evaluation and Quality](https://jobs.ashbyhq.com/cursor/2bbe9f02-83a5-4173-98be-9085d1cb5693)

这说明“评测工程师”不是写几条 pytest，而是把质量变成可测量、可告警、可回归的工程系统。

### Cursor：Agent Harness

职责包括 agent loop、tools、prompts、execution environment、model routing、
multi-agent coordination 和模型上线评估。

来源：[Agent Harness](https://jobs.ashbyhq.com/cursor/6e6f5bc2-eb32-40e2-bba9-cfa56479600d)

### Decagon：Agent Platform

团队负责 routing、execution logic、tool orchestration、control plane、multi-model
orchestration、safety constraints、latency、reliability、online A/B、offline evaluation、
observability、testing 和 simulation。

来源：[Staff Software Engineer, Agent Platform](https://jobs.ashbyhq.com/decagon/7df0a996-5a9f-496f-9f8b-c302983765b2)

## 二、不同岗位真正想要的技术栈

### AI 应用 / Agent 产品工程师

重点不是“会调 API”，而是能把 Agent 做成产品。

常见技术栈：

```text
Python + TypeScript
FastAPI / Next.js
PostgreSQL + Redis
SSE / WebSocket
Docker / Kubernetes
LangGraph 或自研 Agent Harness
工具调用 / MCP
向量检索 / reranker
OpenTelemetry / LangSmith / Langfuse / Arize / Braintrust
offline evals / online experiments
```

高信号能力：

- Agent 状态机和路由。
- Tool registry、权限、确认、幂等。
- Context compression、记忆读写和淘汰。
- 评测数据集、回归、失败分群。
- Trace 和用户反馈闭环。

### Agent Platform / 基础设施工程师

常见技术栈：

```text
Go / Rust / Java / Python
PostgreSQL / Redis / Kafka / NATS
Temporal 或其他 durable workflow
Kubernetes / Docker / gRPC
vLLM / TensorRT-LLM / SGLang
GPU / CUDA / 推理优化
OpenTelemetry / Prometheus / Grafana
```

关注分布式系统、多租户、并发、隔离、调度、限流、缓存、模型路由和成本。

### Applied AI / Forward Deployed Engineer

要求既有工程能力，又能理解客户和产品：

- Python 和全栈原型能力。
- 快速集成企业系统。
- 评测集和原型验证。
- 部署、排障和沟通。
- 把客户问题转成可复用产品能力。

### Evaluation / Data / Quality Engineer

常见能力：

```text
Python + SQL
大数据与数据管道
golden datasets / synthetic data
LLM-as-a-Judge + human calibration
统计实验 / A-B test
failure taxonomy
annotation workflow
```

这类岗位正在变多，而且与普通后端岗位有明显区别。

### Applied Research Engineer

更强调：

- PyTorch 和 Transformer。
- Post-training、RLHF / DPO / LoRA。
- 多模态和推理研究。
- 分布式训练与推理。
- 论文复现和实验设计。

## 三、协议和安全标准的信号

### MCP

MCP 官方定位是连接 AI 应用与外部数据源、工具和工作流的开放标准。它已经不只是概念，
而是 Agent 工具生态的重要接口。

来源：[Model Context Protocol](https://modelcontextprotocol.io/)

MCP 不是必须从零实现协议，但项目应该知道：

```text
工具发现
权限边界
调用确认
结果序列化
错误处理
```

### A2A

A2A 面向 Agent 之间的协作，但目前采用度和岗位提及率仍低于 MCP。它值得关注，
不必为了简历优先实现。

来源：[A2A Protocol](https://a2aproject.github.io/A2A/latest/)

### OpenTelemetry GenAI

生成式 AI 的可观测性正在向统一语义约定靠拢，意味着 trace、span、模型调用、工具调用、
token、延迟和错误需要结构化，而不是只打印日志。

来源：[OpenTelemetry GenAI Semantic Conventions](https://opentelemetry.io/docs/specs/semconv/gen-ai/)

### OWASP LLM Top 10

2025 版重点关注：

- Prompt Injection。
- Sensitive Information Disclosure。
- Improper Output Handling。
- Excessive Agency。
- System Prompt Leakage。
- Vector and Embedding Weaknesses。
- Unbounded Consumption。

来源：[OWASP Top 10 for LLM Applications 2025](https://genai.owasp.org/llm-top-10/)

这正好对应 TeachX 后续需要的工具权限、参数脱敏、输出处理、消费预算和向量安全。

## 四、国内团队开源产品体现的方向

### Coze Studio

核心能力包括 prompt、RAG、plugin、workflow、knowledge base、memory、多模型配置、
调试和部署。这说明国内 Agent 平台正在把“开发、调试、发布、运行”做成完整闭环。

来源：[coze-dev/coze-studio](https://github.com/coze-dev/coze-studio)

### AgentScope 2.0

官方 README 列出的能力很接近当前主流 Agent 平台要求：

- Agent Loop。
- Toolkit 和工具调用。
- Context：自动压缩、工具结果卸载、上下文注入。
- Event System：流式推理、工具调用和多模态事件。
- Permission & HITL：细粒度权限、确认和绕过模式。
- Middleware：回复、推理、行动、模型调用、权限和上下文压缩钩子。
- Memory：可切换后端。
- Workspace / Sandbox：本地、Docker、E2B、Daytona、K8s 等隔离执行。
- Agent Service：多租户、多会话、FastAPI、Web UI。
- Agent Team：Leader-worker 编排、任务规划。
- Channels：飞书、Discord 等渠道。
- RAG Service：对象存储、索引 Worker、多租户检索。
- MCP & Skill Hub。
- Persistence、Scheduling 和后台任务卸载。

来源：[agentscope-ai/agentscope](https://github.com/agentscope-ai/agentscope)

这份 README 是判断“最新主流 Agent 技术栈”的高质量参考。

## 五、TeachX 哪些已经踩中，哪些还差

| 能力 | TeachX 现状 | 招聘价值 |
| --- | --- | --- |
| 流式 Agent Loop | 已有，手写实现 | 基础项 |
| 工具调用 | 有 calculator / knowledge search | 基础项，需要升级为 Harness |
| RAG | FTS5 + 向量 + RRF | 有基础，缺真实质量和 reranker |
| 用户隔离 | JWT、Cookie、owner_id | 加分项 |
| 密钥安全 | Fernet 加密用户 Key | 加分项 |
| 成本控制 | usage、预算、输出限制 | 高信号，已经不错 |
| Provider 错误映射 | 超时、429、5xx、断流 | 高信号 |
| Evaluation | 缺离线数据集和回归指标 | 当前最大短板 |
| Observability | 缺 trace、span、失败分群和告警 | 当前最大短板 |
| Context / Memory | 有历史和学习档案，缺摘要、长期记忆和淘汰策略 | 下一重点 |
| Tool permission / HITL | 缺审批、副作用分级和沙箱 | 下一重点 |
| Model routing | 只有单连接切换，缺复杂度路由和 fallback 策略 | 中高价值 |
| MCP | 后端主线未实现 | 中高价值 |
| Deployment | Docker 未实机验证，未上线 | 简历和面试都需要 |

## 六、按招聘价值重新排序 TeachX

建议不要继续按“Redis、Chroma、Milvus、RAGAS”逐一堆名词，而是按下面的顺序做：

### P0：Agent Harness 可靠性

- Tool policy。
- Retry / timeout。
- Idempotency。
- Permission / human approval。
- Sensitive argument redaction。
- 多工具执行策略。

### P1：Evaluation + Observability

- 结构化 trace 和 span。
- 固定评测数据集。
- 离线 replay。
- RAG Recall@K、MRR、Hit@K。
- 引用质量、回答忠实度。
- 回归测试和 quality dashboard。
- 真实用户反馈进入失败分析。

这一批完成后，项目会从“能跑的 AI 应用”升级为“能证明质量、能持续改进的 AI 系统”。

### P2：Context Engineering + Memory

- 对话摘要。
- 工具结果卸载和压缩。
- 长期学习记忆。
- 记忆检索、更新、删除和过期。
- 上下文预算与优先级。

### P3：真实 Retrieval 质量

- 真实 Embedding。
- 混合检索对比。
- Reranker。
- 权限过滤和来源引用。
- 模型升级后的 reindex。

### P4：MCP、Skills、Sandbox

- MCP Client 和 Server。
- Skill 动态加载。
- 工具权限和人类确认。
- Docker / E2B 等执行隔离。

### P5：Model Routing + Durable Execution

- 根据复杂度、成本、延迟选模型。
- 模型降级和 fallback。
- 流式 token / latency 指标。
- 后台任务和可恢复工作流。

### P6：部署、安全与在线演示

- Docker 实机构建。
- 在线 Demo。
- 监控、日志、告警。
- Prompt Injection 和权限测试。

## 七、简历上真正高信号的表达

### 高信号

```text
Agent Harness
Tool Orchestration
Tool Permissions / Human-in-the-loop
Offline Evaluation / Golden Dataset
Regression Suite / Failure Taxonomy
LLM-as-a-Judge + Human Calibration
Tracing / Observability
Context Engineering / Memory
Model Routing / Cost-Latency Optimization
Hybrid Retrieval / Reranking
MCP / Sandboxed Execution
Durable Workflow
```

### 低信号

```text
调用 LLM API
支持流式输出
接入 Redis
接入向量数据库
使用 LangChain
能做 RAG
```

这些不是没价值，而是太基础，不能单独承担项目的主要技术卖点。

## 八、对 TeachX 的最终建议

TeachX 不需要变成另一个 Coze 或 AgentScope。更适合我们的路线是：

```text
真实多用户学习产品
+ 自研可解释 Agent Harness
+ 可复现评测和 observability
+ 长期学习记忆
+ 可控工具权限
+ 在线演示
```

最先做的三项应是：

1. 工具 Harness 的重试、幂等、权限和脱敏。
2. Evaluation 数据集、RAG 指标和 trace。
3. Context / Memory 的摘要、检索和淘汰策略。

完成后再补 MCP、Reranker、Model Routing 和部署。这样写出的项目经历，
比简单罗列 Redis、Chroma、Milvus 和 RAGAS 更难被面试问倒。
