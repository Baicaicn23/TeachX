# Agent 开发面试 · 一页纸问答稿

> 从 24 篇教程的面试问答提炼的高频 10 题,每题给"30 秒答法"。
> 数字口径:91 项自动测试、Hit@3 = 1.0、MRR = 0.688(以仓库当前README/评测命令输出为准)。
> 答题公式:**结论先行 → 关键机制一句话 → 主动说一个 trade-off 或坑**。

---

### 1. 为什么自研 Agent Loop,不用 LangChain?

这是学习项目,自研本身就是目的——重试、幂等、超时、评测这些"框架帮你做了"的事,恰恰是我想吃透的。工程上我的接口很小:Provider 只有 complete/stream 两个方法,工具是 ToolRegistry 统一执行,所以真要换框架,替换的是适配器不是业务代码。代价是生态能力(MCP、记忆)要自己做,我按优先级在补。

### 2. 怎么保证工具不被重复执行?

每个业务请求算一个**稳定幂等键**:user/session/turn/call_id + 参数指纹(canonical JSON 后 SHA-256)再整体哈希。执行前先 INSERT 一条 running 记录,表的主键唯一约束 + 原子插入就是并发控制——插入成功才执行,冲突方直接重放已保存结果。崩溃恢复靠 stale 接管:running 超 300 秒视为可接管。坑:幂等键必须用**原始参数**算,用脱敏后的值会让不同请求误判为同一个。

### 3. 重试策略怎么设计的?

先分类再重试:参数/业务错误(ToolError)永不重试;临时错误和超时按指数退避(200ms 起步、封顶 2s)有限重试;未知异常默认当永久处理——没确认可恢复性和幂等性之前,盲目重试不安全。每次尝试的次数、延迟、耗时都进事件元数据,可观察比"悄悄重试"重要。

### 4. 多工具并发要考虑什么?

**按风险分组**:连续的只读调用一批,信号量限流并发(默认 4);有副作用或未知工具单独串行。顺序用 asyncio.gather 保证——返回顺序等于传入顺序,与完成顺序无关。副作用串行不是性能疏忽:两个不同参数的副作用调用即使各自幂等,同时执行仍可能在业务层交错(比如两次库存扣减并发读改写)。

### 5. RAG 的效果怎么证明?

固定评测集(语料 + 查询 + gold 关键句)跑**和生产完全相同的检索管线**,报三个指标:Hit@K(能不能找到)、Recall@K(找全没有)、MRR(排多前)。基线 JSON 提交在仓库,改动后跑对比命令,任一指标掉超 0.05 容差就非零退出——检索退化是机器拦的,不是人感觉的。当前基线 Hit@3 = 1.0、MRR = 0.688,排序还有优化空间,这就是下一个工作项。

### 6. Agent 出错怎么定位是哪层的问题?

事件流本身就是 trace:每个回合的 tool_call / tool_result / error / done 都带稳定错误码、尝试次数、时间戳并持久化。写了个分析器按错误码映射五层责任:模型(超时/限流/断流)、检索(knowledge_search 失败)、工具、编排(整回合超时/轮数耗尽)、费用(预算),一条命令输出诊断。没见过的错误码归"未知层"不猜——**错误的定位比没有定位更危险**。

### 7. 上下文和成本怎么控制?

三层上限:输出 token、历史消息(条数 + 字符)、单个工具结果,超了就截断;每次模型调用记 token 用量(缺失时估算并打标),用户可设每日预算,超限选择阻止或回退 Mock 模型。原则是让失控在花小钱时被发现,而不是在账单里被发现。

### 8. 敏感信息怎么防泄露?

工具自己声明哪些参数名敏感,事件和持久化记录里这些字段的值统一替换成 ***(保留字段名、隐藏值)。两条边界:发给模型的原始参数不打码——执行链路需要真值;幂等键继续用原始参数哈希——脱敏规则变化不影响去重。工具把 secret 写进返回正文的情况,执行层不自动打码(无法区分业务文本),靠声明 + 代码评审,这是主动承认的未解问题。

### 9. 用户自带模型 Key 怎么处理?

统一 Provider 接口 + OpenAI 兼容适配器,每回合读当前用户激活的连接动态构造 Provider,没有就回退平台默认。Key 用 Fernet 基于服务端密钥加密,接口只返回"是否存在",永不回传明文或密文;换服务端密钥会导致旧 Key 不可解密,这个 trade-off 我写进了文档。

### 10. 调用失败时,用户看到什么?

统一三类稳定错误码(turn_timeout / max_rounds_exceeded / stream_interrupted),全部标记 retryable + turn_terminal;已流出的部分回答保存并标 partial,**不伪装成完整回答**;前端根据 retryable 显示原因和一键重试。以前轮数耗尽会发一段罐头道歉文当正常回答存下来——改成诚实失败是我特意修的契约。

## 高频追问应急句

- 被问"线上怎么办":说明项目定位是作品集,但方案按多机可扩展设计过——幂等表换 PostgreSQL、INSERT OR IGNORE 换 ON CONFLICT DO NOTHING 即可,键是纯函数,不需要分布式锁。
- 被问"最大的坑":Remotion/异步之外,技术侧最值得讲的是 **StopAsyncIteration 穿不过 asyncio.wait_for** 的 Task 语义问题(先转哨兵值),以及"轮数耗尽发罐头文本伪装回答"这种契约级 bug。
- 被问"下一步":忠实度评测(LLM-as-a-Judge)、MCP Client、上下文摘要压缩——每个都能对回调研文档的优先级。
