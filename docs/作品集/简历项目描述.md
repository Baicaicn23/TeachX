## 版本 2:面试口述(STAR 结构)

**S(背景)**:我想验证一件事——把大模型做成可靠、可评测的系统,而不是调一次 API 的封装。所以做了一个多用户 AI 学习平台 TeachX,核心是自研的 Agent 运行时。

**T(任务)**:重点解决三个面试官最关心的问题:① 有副作用的工具被重复执行怎么办;② 出了故障怎么快速定位是哪一层的锅;③ 检索和回答的质量怎么证明,而不是"感觉还行"。

**A(做法)**:
- 可靠性:给每个工具声明执行政策(只读、重试上限、超时);幂等用"稳定幂等键 + 执行记录表唯一约束"——键由用户、回合、调用 ID 和参数指纹做 SHA-256,原子插入抢执行权,重复请求直接重放第一次的结果;敏感参数在事件和记录里统一打码
- 可观测:每个回合的完整事件流(错误码、尝试次数、时间戳)都持久化,写了一个分析器把失败按稳定错误码定位到模型/检索/工具/编排/费用五层
- 可评测:固定评测集跑真实检索管线,输出 Hit@K / Recall@K / MRR,基线存进仓库,指标退化超容差直接报错

**R(结果)**:91 项自动测试全绿(全程 Mock 零消耗);检索 Hit@3 = 1.0、MRR = 0.69,且任何退化会被门禁自动拦下;任何一次失败可以用一条命令定位到责任层;成本上有 token 计量、日预算和多级上下文上限兜底。

**备弹**(被追问时的延伸点):为什么不用 LangChain(可控性 + 这些机制本身就是考点)、为什么唯一约束比内存字典可靠(重启/多进程/先查后写竞态)、如果执行成功但写记录失败怎么办(诚实承认是 exactly-once 的固有缺口,stale 接管兜底)。
