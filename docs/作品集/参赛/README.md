# 参赛材料

> 面向**全国大学生数字媒体科技作品及创意竞赛**的申报材料。
> 申报赛道：**（十三）智慧教育与智能软件类赛项**。
> 作品名：**TeachX 智学助手**（面向大学生的 AI 学习助手）。

## 这个目录是什么

项目的技术内容都在仓库其余部分（`README.md`、`docs/tutorials/`、
`docs/参考/`）。本目录只放**竞赛申报视角**的材料——把已有能力按要求
重新组织、补齐合规文件，并**逐条核对材料与代码的一致性**。

```text

第一次接手：01 → 06（先看还缺什么）→ 02（核对哪些话不能写）
提交前：    06（逐项打勾）→ 05（处理授权项）→ 04（确认披露）
```

## 重心说明

**材料的主体是五组八块核心能力**：

```text
骨架 · 后端框架     大脑 · Agent 设计     手脚 · 工具系统 + MCP
数据 · 记忆 + RAG + 上下文管理            底线 · 数据安全与多用户隔离
```

评测（考卷、双基线、trace 归因）是**支撑证据**，不是主角——它只在
[01](01-作品说明.md) §8.10 和 [07](07-答辩要点与PPT提示词.md) 第 13 页占一小块。
原因：答辩要求"团队熟悉作品"，讲不清楚的内容是负担不是资产。
评测仍然保留，因为它撑着 20 分的「完成度与可验证性」。

## 三条重要提醒

1. **写材料前先看 [02-主张与证据核对表](02-主张与证据核对表.md)**。竞赛把
   "材料与实际成果一致"列为前置审查条件——材料写得比实际做得多，会直接
   失去评分资格。该表已标出 3 处原文夸大项和正确表述。

2. **[06-前置条件自查](06-前置条件自查.md) 里有 7 项信息需要团队提供**，
   开发方无法代填（团队人数、成员分工、指导教师、申报单位、报名编号、
   报名与提交截止时间）。

3. **[05-来源与授权清单](05-来源与授权清单.md) 标出 2 项需要处理的授权风险**：
   `knowledge-engine-icons` 与 `agent-icons` 中保留了第三方品牌 logo，
   而它们对应的功能本作品并未实现（属上游遗留死 UI）。建议随 UX 清理一并移除。
