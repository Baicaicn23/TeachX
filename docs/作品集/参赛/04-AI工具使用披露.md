## 一、本作品的特殊性：它既是"AI 应用"，也是"使用 AI 工具开发的作品"

多数参赛作品的披露只需要说明"用 AI 辅助做了什么"。本作品需要**分两类**说明：

| 类别 | 含义 | 本作品的情况 |
| --- | --- | --- |
| **类别 A：被测对象** | 作品**产品内部**调用的大模型 | 用户提问时调用 DeepSeek 等模型生成回答——这是**作品的功能**，不是"辅助创作" |
| **类别 B：开发工具** | 开发**过程中**用于辅助编码、文档整理的 AI 工具 | 如实说明使用环节与人工把控方式 |

> **关键区分**：类别 A 是作品的功能组成部分（如同一个编译器项目调用开源编译器），
> 类别 B 才是竞赛第十条所指的"帮助克服技术困难"的 AI 工具辅助。二者不可混为一谈，
> 材料中必须分开陈述。

## 二、类别 A：作品内部调用的模型与开源依赖

### 2.1 产品运行时可调用的模型

| 模型 / 服务 | 用途 | 接入方式 | 是否必需 |
| --- | --- | --- | --- |
| **Mock Provider**（自研） | 本地开发、自动测试、零成本演示 | 项目内置 | 默认，可独立演示全部功能 |
| DeepSeek（`deepseek-flash` 等） | 真实对话生成 | OpenAI 兼容接口 | 可选，需用户提供 Key |
| 任意 OpenAI 兼容平台 | 真实对话生成 | 自定义 Base URL | 可选，需用户提供 Key |
| 智谱 `embedding-3` | 真实向量检索 | OpenAI 兼容 Embeddings 接口 | 可选，默认使用 Mock Embedding |

**说明**：本作品**不绑定任何特定供应商**。用户可在"模型连接"页填入自己的 API Key，
服务端加密存储（Fernet），接口不回传凭据。产品的完整能力（意图路由、检索、
工具循环、评测）在 Mock 模式下**全部可演示且无需任何 API 额度**。

### 2.2 关键开源依赖

| 依赖 | 用途 | 许可证 |
| --- | --- | --- |
| FastAPI / Uvicorn | HTTP 与 WebSocket 服务 | MIT / BSD-3-Clause |
| Pydantic / pydantic-settings | 数据校验与配置 | MIT |
| SQLite（Python 内置 `sqlite3`） | 数据持久化（含 FTS5 全文检索） | Public Domain |
| pypdf | PDF 文本提取 | BSD-3-Clause |
| bcrypt / PyJWT | 密码哈希 / 会话令牌 | Apache-2.0 / MIT |
| cryptography | API Key 加密（Fernet） | Apache-2.0 / BSD |
| httpx / openai | 模型调用 | BSD-3-Clause / Apache-2.0 |
| Next.js / React | 前端界面 | MIT |

> **重要声明**：本作品的 **Agent Harness 为自行实现**，不依赖 LangChain、AutoGen、
> CrewAI、LlamaIndex 等 Agent 框架。工具调用循环、上下文压缩、MCP 客户端、
> 意图路由、评测体系全部为原创实现。详见
> [02-主张与证据核对表](02-主张与证据核对表.md)。

## 三、类别 B：开发过程中使用的 AI 工具（如实说明）

> ⚠️ **本节的工具名称与使用比例需要作者本人确认填写**。以下为仓库与开发文档中
> 可确证的信息，作者应在提交前核对并补全。

### 3.1 使用的 AI 工具

| 工具 | 使用环节 | 说明 |
| --- | --- | --- |
| AI 编程助手（Claude Code 等） | 代码编写、重构、测试补全、文档撰写 | 辅助编码与文档整理 |
| AI 编程助手（ZCode 等） | 环境配置、网络与镜像配置协助 | 开发环境搭建 |
| AI 编程助手（Codex 等） | 早期代码与文档 | 见项目文档记录 |

### 3.2 使用范围（对照竞赛第十条的允许范围）

竞赛第十条规定，AI 工具使用范围**限于**"帮助参赛团队在训练阶段克服技术困难、
实现预期功能、完成必要测试编译"，**不得用于参赛作品创意内容的生成**。

本作品的执行情况：

| 竞赛要求 | 本作品实际做法 |
| --- | --- |
| 可用于克服技术困难、实现功能、测试编译 | ✅ 用于代码编写、调试、测试补全、环境配置 |
| **不得用于创意内容生成** | ✅ **作品创意、产品定位、教学理念、架构设计均为作者提出**；AI 未参与选题与创意构思 |
| 引用他人内容须注明来源与授权 | ✅ 见 [05-来源与授权清单](05-来源与授权清单.md) |

### 3.3 人工实质性贡献（必须如实列明）

以下工作为**作者本人完成**，AI 工具仅作辅助：

1. **选题与创意**：从自身备考痛点出发，确定"让学科知识库成为平时的沉淀罐、
   期末从库里长出复习材料"的产品方向
2. **教学理念设计**：四项元认知教学技能（主动回忆闸门 / 信心校准 / 生产性失败 /
   独立完成检查点）的取舍与提示词落地
3. **架构设计**：八层架构、自研 Harness 的边界划分、模块接缝定义
4. **关键算法实现**：FTS5 trigram 中文分词重建迁移、同义词查询扩写表、
   RRF 混合排序、跨库回退策略
5. **评测体系设计**：双卷双基线、意图考卷（38 条标注样本）、任务级考卷（7 条
   任务断言）、trace 五层归因的责任层定义
6. **系统整合**：前后端集成、WebSocket 协议设计、多用户隔离规则
7. **验证与结论**：全部评测数据由作者实跑并核对
