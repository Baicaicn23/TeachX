## 一、这个项目是什么（自包含简介）

**TeachX 是一个面向大学生的 AI 学习助手**：Web 优先（Next.js 前端 +
FastAPI 后端 + SQLite），围绕"**把大模型做成可靠、可评测的学习系统**"
构建。它不是"调一次模型 API"的封装，而是一个自研 Agent Harness，四天
高强度开发完成了完整的能力栈：

- **意图识别 + 多 Agent 路由**（P0）：六类教学意图 → 六个子 agent
  （专属提示词 + 工具最小权限，schema 与执行双层拦截）；
- **端到端评测**（P1）：任务级考卷（路由/工具/内容断言）进 CI 门禁 +
  LLM-as-a-Judge 手动体检 + 失败自动归因五层；
- **检索召回优化**（P2）：FTS5 trigram 中文分词重建迁移 + 同义词查询
  扩写 + 跨库回退（关键词卷 MRR 0.688→0.938、语义卷 0.639→1.000）；
- **长期记忆 + 在线监控**（P3）：跨会话记忆（规则抽取/注入/可管理）+
  事件流聚合监控 CLI（失败率/空检索率/意图分布/P50·P95）；
- **学生主线**（用户自身痛点驱动）：聊天随手沉淀题目进学科知识库、
  发图即问（多模态附件透传，8 张上限）、PDF/TXT/MD 附件文本内联、
  五学科期末知识库、多学科目标与学科标签记忆、导师提示词 v2.1
  （四项元认知教学技能：主动回忆闸门/生产性失败/信心校准/独立完成
  检查点）。

更早的地基（不要重做）：流式 Agent Loop、知识库 RAG（FTS5+向量+RRF）、
多用户隔离、练习复习闭环、错题记录、工具重试/幂等/脱敏/并发/超时
（E1~E5）、检索评测基线门禁（E6a）、回合 trace（E6b）、真实 Embedding
对比（E8）、上下文摘要（E7）、自写 MCP stdio 客户端且已接官方
Filesystem server（E9a）、费用控制（M16）、作品集材料（三支视频/简历/
面试稿）。完整历史见[开发路线图](规划/开发路线图.md)。

**项目定位**：简历作品集（Agent 开发实习方向），不追求生产上线。
一切决策以"面试官会不会问、能不能讲清原理"为准。

## 五、验证与评测命令

```bash
./scripts/check.sh                    # Ruff + 171 后端测试 + 前端 typecheck
cd backend
uv run python -m teachx.evals.run_rag_eval --baseline evals/baselines/rag_retrieval.json
uv run python -m teachx.evals.run_rag_eval --dataset evals/datasets/rag_retrieval_semantic.json --baseline evals/baselines/rag_retrieval-semantic-mock.json
uv run python -m teachx.evals.run_intent_eval         # 意图考卷(38 条,门槛 0.90)
uv run python -m teachx.evals.run_agent_eval          # 任务级端到端考卷(7 条)
uv run python -m teachx.runtime.monitor --db ../data/teachx.db --hours 0   # 在线监控
```

三套考卷（检索双基线 + 意图 + 任务级）+ 基线门禁是本项目的质量底线：
**任何改动导致考卷变红，先修代码或带着证据更新基线，不要绕过**。
LLM-as-a-Judge（`run_agent_judge`）会消耗真实额度，必须 `--yes` 且仅在
手动验证时小样本运行（≤20 题）。

## 六、架构速览与关键代码入口

```text
浏览器 → /ws 统一回合协议
  → 预算检查 → 意图识别(runtime/intents.py，规则+LLM 两层)
  → 子 agent 路由(AGENT_PROFILES：专属提示词+工具策略)
  → 系统提示词组装(prompts.py：能力+子agent+档案+长期记忆)
  → Agent Loop(engine.py：流式、工具循环、重试/幂等/并发/超时)
  → 事件流持久化(messages.events) → trace 诊断 / 监控聚合
```

| 改哪 | 看哪 |
| --- | --- |
| 意图/子 agent/工具策略 | `runtime/intents.py` + `engine.py` 的 `_enabled_tools_for` |
| 检索(trigram/扩写/回退) | `knowledge/service.py` + `knowledge/query_rewrite.py` |
| 提示词(四层) | `runtime/prompts.py`(基础/能力/档案) + `intents.py`(子 agent 角色) |
| 评测(三套考卷) | `evals/run_rag_eval.py` / `run_intent_eval.py` / `run_agent_eval.py` |
| 监控/trace | `runtime/monitor.py` / `runtime/turn_trace.py` |
| 长期记忆 | `memory/service.py`(subject 学科标签) |
| MCP | `runtime/mcp_client.py`(已接官方 Filesystem server，纯配置) |

架构全文见[架构与数据流](参考/架构与数据流.md)。

## 八、已知限制与坑（完整清单）

- **直接 `uv run pytest` 会漏本地 .env 的认证配置**导致 test_api 401——
  **以 check.sh 为准**（它强制 Mock 并关闭认证，不要移除这些覆盖）。
- 自定义测试 Provider 会被意图识别多调一次 `complete`；测试意图无关
  行为时加 `intent_llm_enabled=False`（参考 test_cost_control）。
- 推理型模型会把输出预算花在思考上：默认 `TEACHX_MAX_OUTPUT_TOKENS=
  1024` 可能截断到空回答（会诚实报 `output_truncated`），联调建议 4096；
  Judge 的评审调用预算同理固定 1024。
- FTS 是 trigram 索引：2 字中文词进不了 FTS 通道（LIKE 兜底+向量补偿）；
  改 `knowledge/query_rewrite.py` 词表前先跑检索双基线。
- 规则意图分类器有误判边界（"第 3-4 章"被当减法）；意图仅六类，未识别
  归兜底 smalltalk。
- 练习 agent/进度 agent 无工具是最小权限设计而非缺陷；自定义测试
  Provider 注意 `tool_not_allowed` 执行层拦截。
- 本机网络：github.com 走 SSH(443) 可达；HTTPS 直连被本机代理的自签名
  证书 MITM——urllib 直连会 SSL 报错，用 httpx 或走代理
  (`export https_proxy=http://127.0.0.1:8086`)。
- 数据备份：历史数据在 `data/backup-20261006*/`，重置数据前先备份。
- `run_agent_judge` 是唯一花真实额度的脚本：Mock Provider 拒跑、必须
  `--yes`、报告写 `evals/reports/`（gitignored）。

## 九、开发规则（必须遵守）

```text
明确用户场景 → 代码 → 自动测试(Mock,零 API 消耗) → 浏览器或 API 验证
→ 中文教程(≥8 面试问答) → 更新 README/路线图/交接文档 → commit → push
```

- 提交规范：`feat:` 功能与测试；`docs:` 教程与文档。推送前跑
  `./scripts/check.sh` + `git diff --check`。
- **绝不**：测试读真实 Key、输出/提交任何 Secret、无验证声称完成、
  绕过考卷门禁、删除 `data/` 下的数据库与知识库原文（重置前先备份）。
- 大功能教程结构参考教程 25~28（用户场景→步骤→原理→常见错误→验证→
  边界→面试问答→自测题）。
