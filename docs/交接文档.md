## 项目目标

TeachX 是一个 Web 优先的 AI 学习平台：浏览器聊天与流式回答、自研 Agent
Harness、知识库与 RAG、个性化学习闭环、用户自带模型连接。完整介绍见根目录
[README](../README.md)。项目定位：**简历作品集**（Agent 开发实习），
生产部署硬化不在计划内。

当前明确暂缓：管理员用户管理、Docker 实机构建、PostgreSQL 迁移、
复杂插件市场。

| P1 | 端到端 Agent 评测（任务级断言 + 小样本 Judge + 失败归因） | **已完成**（`d86b223`） |
| P2 | 检索召回优化（查询改写 → 参数调优 → 空结果回退，每步量化） | **下一步** |
| P3 | 跨会话长期记忆 + 在线监控聚合（失败率/空检索率/时延分位） | 等 P2 |
| 可选 | MCP 接真实 server + 权限确认；忠实度评测；Reranker | 穿插 |

P2 设计要点（详细版见路线图）：查询改写（同义词表 → LLM 改写）→ 召回

（`evals/datasets/rag_retrieval_semantic.json`）量化 RR/Hit 变化**，退化被
基线门禁拦截，P1 的任务考卷做行为回归兜底。

## 已知限制与坑

- 前端“资源面板”的工具目录是静态清单，后端动态注册的 MCP 工具不在其中
  显示（前端同步是 E9b 的一个小任务）。
- “执行成功但写幂等终态失败”的窗口在 stale 接管时仍可能重复副作用，
  教程 19 有说明。
- usage 依赖供应商返回值，缺失时估算并标记 `estimated`。
- 评测集是小考卷（8+6 题），能抓回归，不代表真实查询分布。
- 直接 `uv run pytest` 会漏本地 `.env` 的认证配置，**以 check.sh 为准**。
- 原前端仍有大量非主线页面，只保证列出的路径完成验证。
- Docker、PostgreSQL、管理员功能不是阻塞项，不要投入。
- 意图规则分类器有误判边界（如“第 3-4 章”被当成减法）；意图只有六类，
  未识别归兜底 smalltalk 走默认对话；前端不显示 intent 字段（只见于事件与
  metadata）；进度子 agent 无只读数据工具，仅依据注入档案回答。扩展方式见
  教程 25 的“当前边界”。
- 自定义测试 Provider 会被意图识别多调一次 `complete`；测试意图无关行为时
  在 AgentRuntime 构造里加 `intent_llm_enabled=False`（参考 test_cost_control）。
- 推理型模型（DeepSeek R 系等）会把输出预算花在思考上：默认
  `TEACHX_MAX_OUTPUT_TOKENS=1024` 可能截断到空回答（现在会诚实报
  `output_truncated`），本地联调建议 4096；Judge 的评审调用预算同理已固定
  为 1024，不要调回 128。
- `run_agent_judge` 是唯一会花真实额度的脚本：Mock Provider 拒跑、必须
  `--yes`、报告写 `evals/reports/`（gitignored，不可复现、不进 Git）。
